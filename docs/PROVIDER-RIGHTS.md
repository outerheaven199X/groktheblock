# Provider rights register

This is a working register, not legal advice. Nothing in it says any use is permitted. **Every row is "unverified, needs review/permission"** until someone with authority reads the current terms (and, where needed, gets written permission) and records the outcome here.

**Default posture:** Grok The Block is software each user runs themselves, locally or on their own Grok Bot, for their own analysis. The project does not operate a central feed that rebroadcasts provider data. Anyone who wants to publish signals publicly, run a shared feed, or sell access should resolve the relevant rows first. **A row marked "unverified" is not permission.** No shared feed, auto-publishing of provider data, or public derived-alert path exists in this repo, and none should be added until the rights for that exact use are recorded here. A user-supplied API key is not by itself a right to broadcast that data or alerts derived from it.

Calendar contact: BLS and SEC ask automated clients for a contact. It is configured per user through `GTB_CONTACT` (calendar) and `GTB_SEC_USER_AGENT` (EDGAR). This repo ships with **no contact configured** (`data/event-calendar.json` → `contact.configured: false`); the BLS rows in the shipped calendar were fetched with a placeholder test contact and should be rebuilt.

## Public samples (R5-02)

**Basis for anything committed to this public repo: synthetic, or nothing.** Because no row above is verified, no raw or derived provider payload is a public sample.

- Parser contract fixtures: `tests/fixtures/contracts/synth.py`, invented values in each provider's public response shape, labelled `"_provenance": "synthetic"`.
- `examples/signals-EXAMPLE.json` and `docs/signals-*.png`: generated from synthetic inputs (`tests/fixtures/contracts/make_example.py`), with `"synthetic": true` and a `[SYNTHETIC]` prefix on every title. Hashes: `docs/screenshots-provenance.json`.
- Real responses saved for developer verification live only in `tests/fixtures/private/` (gitignored, never committed); `tests/test_private_fixtures.py` runs on them locally and prints SKIPPED elsewhere.
- `tests/test_round5.py::test_R5_02_static_scan_*` fails if a tracked file carries a recognisable vendor payload shape without the synthetic marker.
- On-chain token examples (`examples/scan-*`, `wallet-*`, `replay-*`, `watch-*`, `shill-*`, `leaderboard-*`, `threats-sample.json`): **synthetic** since round 6 (`tools/synthesize_onchain.py`; real originals only in gitignored `tests/fixtures/private/onchain/`). Every image in the tree is rendered from synthetic examples. `docs/verification/` evidence files were removed from the tree. Every public asset is classified in `docs/assets-manifest.json` (sha256, source, status); `tests/test_round6.py` fails on an unclassified or changed asset.
- Git history still contains the earlier real payloads (see `docs/review/ROUND5-RESULTS.md`); history was not rewritten.
